# 캐릭터 모델링 뷰어

게임에 넣기 전에 캐릭터 하나만 따로 띄워 보고 다듬는 작업장. 새 캐릭터는 여기 있는 뷰어를
복사해 몸통 만드는 부분만 갈아 끼우는 식으로 만든다.

| 파일 | 내용 |
|---|---|
| `three.r128.min.js` | 게임 `index.html`에 동봉된 것과 **같은** three.js r128을 그대로 떼어낸 것 |
| `glutton_ghoul_viewer_v3.html` | 거대 구울(폭식 구울). 현재의 베이스 |

## three.js는 CDN에서 받지 않는다

두 가지 이유로 로컬 `three.r128.min.js`를 쓴다.

- 작업 환경의 브라우저는 바깥 CDN에 못 나간다(`ERR_TUNNEL_CONNECTION_FAILED`). CDN을 걸어 두면
  뷰어를 **렌더해서 확인하는 검증 자체가 불가능**하다.
- 버전이 게임과 어긋나면 뷰어에서 맞춰 놓은 모양이 게임에 넣었을 때 달라진다.

## 베이스에 이미 들어 있는 것 — 새로 짜지 말 것

- **게임과 같은 렌더 파이프라인**: 저해상도 렌더 타깃(픽셀화) + 깊이 차이 기반 검은 외곽선 +
  ACES 톤매핑. 뷰어에서 본 실루엣이 게임에서도 같게 나오는 이유다.
- **게임과 같은 머티리얼 헬퍼**: `getLowPolyMat`(=`flatShading: true`), `jitterGeometry`.
  둘 다 게임 코드에 같은 이름·같은 동작으로 있으므로 옮길 때 그대로 붙는다.
- **살덩이 헬퍼**: `lump`(울퉁불퉁한 혹), `tumorShell`(타원면을 혹으로 뒤덮기),
  `addSeam`(정맥/균열), `addSpike`(가시), `blade`(표면을 타고 도는 칼날 조각).
- **드로우콜 병합**(`mergeStatic`/`mergeGeos`): 움직이지 않는 조각을 머티리얼별로 하나로 합친다.
  구울은 이걸로 380여 개 → 20개 미만. **애니메이션으로 움직일 그룹은 `skip` 인자로 빼 둘 것.**
- **그리드 토글**: 좌표 숫자가 붙은 격자(`그리드` 버튼). 부위 위치를 눈으로 집을 때 쓴다.
- 자동회전 / 드래그 회전 / 휠·핀치 확대 / 시점 리셋, 모바일 터치·세로 화면 대응.

## 손대기 전에 알아 둘 것

- **정면은 로컬 -z. 게임과 같은 규약이니 절대 뒤집지 말 것.**
  게임은 `rotation.y = Math.atan2(dx, dz) + Math.PI`로 로컬 -z를 표적에 맞추고, 눈·이빨 같은
  얼굴 부품을 전부 음수 z에 둔다(플레이어 -0.32, 일반 몬스터 -0.30, 유령 기사 -0.41 …).
  뷰어도 최상위 그룹을 돌리지 않아서, **게임 몬스터가 `rotation.y = 0`일 때와 똑같은 자세**로 서 있다.
  옮길 때 좌표를 손볼 필요가 없어야 정상이다.
  정면을 보려면 카메라가 -z 쪽에 서야 하므로 `CAM_YAW0`에 π가 들어간다 — **모델이 아니라 카메라를 돌릴 것.**
  (여기에 π를 넣어 모델을 돌려 놓으면, -z 쪽에 놓인 키·언더 라이트가 얼굴·배 대신 뒤통수와 등을
  비추게 된다. 실제로 그랬고, 바로잡으니 정면 평균 휘도가 102 → 123으로 올랐다.)
- 저해상도 버퍼는 **화면과 같은 가로세로 비율**이어야 한다(`calcLowRes`). 가로·세로에 각각
  하한을 두면 세로 화면에서 모델이 찌그러진다.
- 안개(`scene.fog`)는 카메라 거리에 따라 매번 다시 잡는다(`updateCam`). 세로 화면에서 카메라가
  멀어지면 고정 안개가 모델을 배경색으로 덮어 버리기 때문.

## 확인하는 법

```bash
# 1) 문법
S=$(grep -n '^<script>$' viewers/<파일>.html | tail -1 | cut -d: -f1)
E=$(grep -n '^</script>$' viewers/<파일>.html | tail -1 | cut -d: -f1)
sed -n "$((S+1)),$((E-1))p" viewers/<파일>.html > /tmp/v.js && node --check /tmp/v.js

# 2) 실제 렌더 — 정적 서버로 띄우고 동봉 Chromium 으로 스크린샷
npx http-server -p 8125 -s &
```

Playwright는 `executablePath: '/opt/pw-browsers/chromium'`로 동봉본을 직접 가리킬 것
(`playwright install`을 받지 말 것). 실행 인자는
`['--enable-unsafe-swiftshader','--use-gl=swiftshader','--no-sandbox']`.

## 게임으로 옮길 때

게임 쪽 캐릭터는 `createAdvancedMonster`(index.html)에서 타입별로 분기하고, 덩치가 큰 것은
전용 빌더(`buildXxxBody`)를 따로 둔다. 옮길 때 잊기 쉬운 것:

- 방향축은 이미 맞다(위 참고). 최상위 그룹 아래를 통째로 게임 쪽 `grp`에 붙이면 그대로 앞을 본다.
- **살·피부 재질에 `markOrganic`을 직접 걸 것.** 전용 빌더가 바깥 `skinMat`을 가리고 자기 재질을
  만들면 자동으로 안 걸린다(궁중 마법사·혼령이 실제로 이렇게 빠져 있었다). 돌·금속 몸이면 반대로
  제외 목록에 넣는다.
- 뷰어의 조명은 캐릭터 하나를 보기 좋게 맞춘 것이다. 게임의 던전 조명은 다르므로 색은
  게임에 넣고 다시 볼 것.
