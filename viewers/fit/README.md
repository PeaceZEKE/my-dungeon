# 정투영 참고도 → 모델 실루엣 맞추기

`ortho.py` (numpy · Pillow 만)

1. **참고도 검사** — `python3 viewers/fit/ortho.py check <4면도.png> fsbt|ofbt`
   네 그림 높이 편차 · 바닥선 · 정면/후면/위 좌우 대칭 · 정면 폭 = 위 폭 · 측면 깊이 = 위 깊이. `ok:false` 면 다시 뽑는다
   (코덱스가 '정면'이라 해도 3/4 원근으로 그린 그림은 여기서 걸린다 — 기사 투구 첫 4면도·어깨 첫 두 장이 그랬다).
   순서 `fsbt` = 정면·측면(앞이 왼쪽)·후면·위(앞이 아래) · `ofbt` = 바깥 측면(앞이 오른쪽)·정면·후면·위.
2. **비주얼 헐 로프트** — `ortho.loft(path, order, levels, H)` 가 높이마다 정면 윤곽의 폭 · 측면 윤곽의 앞뒤 끝 · 위 윤곽을
   교집합해 단면을 구하고 중심에서 32방향 반지름으로 바꾼 링 `[y, cx, cz, r×32]` 을 돌려준다(앞 = −z). 정면·측면 실루엣이 구조상 맞는다.
   게임 코드는 이 링 표(`HELM_RINGS`·`PAULD_RINGS`)를 그대로 들고 같은 표면 위에 금 띠·눈 틈 같은 세부를 얹는다.
3. **검증은 면적 겹침(IoU)이 아니라 윤곽 거리** — `ortho.contour_dist(ref, ours)` (높이를 맞춘 뒤 평균·최대 거리, 높이 대비 %).
   IoU 0.9 라도 윤곽이 몇 % 어긋나면 눈에는 다르게 보인다.

함정: 렌더 실루엣을 찍을 때 카메라 중심이 물체 가운데가 아니면 위가 잘려 '모델이 납작하다'로 오판한다(어깨에서 겪었다).

## 로프트를 그대로 그리면 안 된다(기사 투구·어깨 2차)

비주얼 헐 링을 그대로 표면으로 쓰면 실루엣은 맞는데 **보기엔 더 이상해진다**(사용자: "더 이상해졌는데?").
① 그림에서 픽셀로 뽑은 반지름이 방향마다 들쭉날쭉해 표면이 물결치고, flatShading 이라 잔 면마다 음영·모서리 하이라이트가 갈려
구겨진 종이처럼 보였다. ② 코덱스 정투영이라도 그림끼리 앞뒤가 안 맞는 곳(어깨 바깥 측면 ↔ 위 그림의 원판 자리, 투구 측면 ↔ 후면 목가리개
밑선)이 교집합에서 깎여 위가 네모나거나 앞이 납작해졌다. 투구의 핵심인 **앞으로 튀어나온 각진 부리**가 교집합에선 오히려 사라졌다.

그래서 **매개 형태 + 윤곽에서 잰 값**으로 바꿨다.
- 투구: `helm_param.py` — 높이마다 옆 반지름(정면 윤곽 · 옆 원판 구간은 보간) · 앞/뒤 끝(측면 윤곽) · 앞쪽 초타원 지수
  (면갑 구간 1.1 = V 부리 평면 둘, 나머지 2 = 둥근 두개골). 높이 방향은 [1,2,1] 두 번으로 다듬는다.
- 어깨: 원화 그대로 '몸 쪽이 트인 종 모양 껍데기'(둥근 머리 → 곧게 퍼지는 옆) · 위판은 닫힌 머리, 트임은 아랫판에만.
- 곡면 분할은 최소로(사용자: "폴리곤은 최대한 적게"): 투구 링 8단 × 12방향, 어깨 위판 10×4 · 아랫판 8×2 — 게임 거리에서는 차이가 안 보인다.
- 곡면은 `hero2Surf` — 인덱스 격자 + 곡면에서 유한 차분으로 잰 법선 + 매끈한 재질(`'ms'`·`'ss'`·`'msd'`).
  조각 가장자리는 안쪽으로만 미분해 면갑 두 판이 만나는 능선이 날카롭게 남는다.
- 판단은 윤곽 거리만 보지 말고 **같은 각도 그림을 나란히** 볼 것(`hero/helm_cmp` 처럼 기준 4면도 아래 렌더 4장).
