# dl-playbot — 플레이 봇 밸런스 측정

근거: `viewers/playbot/README.md`(봇의 능력과 한계 — **먼저 읽을 것**) · `CLAUDE.md` **'2·3막 체감 조정(v826)'** · **'혼령 히트앤런 빈도(v827)'** · **'4막 측정과 조정(v870)'** · **'전체 점검(v871)'** · **'용병 2단계'** 계측 함정 ①②③ · **'렌더 변경을 비교할 때'**(서버는 저장소 루트). 충돌하면 CLAUDE.md 가 이긴다.

봇 자체(`bot.js`·`run.js`)는 저장소 것을 그대로 쓴다. 이 스킬은 묶음 실행·집계만 맡는다 — 봇을 고쳐야 하면 `viewers/playbot/bot.js` 를 고치고 README 에 적는다.

## 1. 서버

```bash
bash .claude/skills/dl-harness/scripts/serve.sh 8899        # 저장소 루트에서 · 버전/내용(md5) 확인
```
`batch.sh` 도 시작할 때 포트마다 서빙 중인 index.html 의 md5 가 작업 트리와 같은지 보고, 없는 포트는 저장소 루트에서 `setsid nohup` 으로 띄운다.

## 2. 돌리기 (저장소 루트에서)

```bash
P=.claude/skills/dl-playbot/scripts
OUT=<스크래치패드>/pb-<주제>             # 결과는 저장소에 넣지 않는다(CLAUDE.md '잡동사니')

# 전/후 비교 — 같은 빌드에서 URL 플래그로 가른다(새 기능은 늘 플래그가 있다)
bash $P/batch.sh -o $OUT -f act2 -f act3 -c all -n 8 -C old='&bal5=0' -C new='' -p 8899,8897
# 막·직업 점검(조건 하나)
bash $P/batch.sh -o $OUT -f 1-30 -f 31-60 -c knight,mage,archer -s 11,22,33,44,55,66,77,88
# 용병 고용 상태로(spear·shield·xbow·monk, :장비 Lv) — 조건 이름에 표시
bash $P/batch.sh -o $OUT -f act3 -c k,m -n 8 -C shield5='' --merc shield:5
bash $P/batch.sh -h                       # 옵션 전체 · --dry 로 일 목록만
```
- **오래 걸린다** — 30층 run 하나 2~5분(부팅 20초 포함, 4막·보스 시간 초과가 많으면 더). 8시드 × 3직업 × 1막 = 24 run ≈ 15~30분. Bash 를 `run_in_background` 로 띄우고 진행은 `bash $P/status.sh $OUT`. 끝날 때까지 기다린 뒤 보고할 것.
- 끊겼으면 **같은 명령을 다시** — `runs/` 에 있는 결과는 건너뛰고 남은 것만 돈다(`--force` 면 전부). 끄기는 `bash $P/stop.sh $OUT`.
- 결과 폴더: `runs/<조건>__<직업>__f<A>-<B>__s<시드>.json`(run.js 출력 그대로) · `logs/` · `done.txt` · `conds.tsv`(조건 → 쿼리·용병) · `batch-<시각>.txt`(버전·md5·git·옵션 — 보고에 버전을 적을 것).
- 시작층은 **1·31·61·91 만** — 그 밖은 `startRunAtFloorReset` 단축 레벨(22/27/30)이 실제 진행과 안 맞는다.

## 3. 집계

```bash
node $P/agg.js $OUT                        # 조건별 → 막 → 직업, 조건이 둘 이상이면 끝에 비교(기준 = 첫 조건 · --base 로 바꿈)
node $P/agg.js $OUT --acts 3 --class m --boss-src --top 6
node $P/agg.js $OUT --md                   # 노션·보고용 마크다운 표
node $P/agg.js $OUT --json $OUT/agg.json
```
읽는 법(한 줄 = 시드 하나가 표본 하나):
- `일반층 사망/층 2.42±0.30` — 보스 층을 뺀 층의 평균 ± 표준오차. 피해/층 = 층마다 잃은 체력 / 최대 체력(중독 포함).
- `피격/층` 은 `hitLog`(damagePlayer 경유) 개수다 — `floors[].hits` 는 체력이 준 프레임 수라 중독 도트가 수천 번으로 잡힌다('2·3막 체감 조정' 계측 함정 ①). hitLog 는 run 당 6000 개 상한 — 넘으면 경고가 뜨고 뒤쪽 층 출처가 빠진다.
- `출처/층 wraith 63%(18/29)` — 그 출처에게 층당 최대 체력의 63% 를 잃음, 한 방 평균 18% · 최대 29%. 한 방 최대가 32·40% 에 몰려 있으면 한 방 상한(BAL5)에 걸리고 있는 것이다.
- `보스 60층 130±11s(초과 1/8) 사망 9.3` — 보스가 깨어나서 죽을 때까지(시간 초과 층은 시간 평균에서 빠지고 따로 센다).
- 비교 줄의 `z` = 차이 / √(SE₁² + SE₂²). **|z| < 2 는 잡음 안** — 그 조정은 이 측정으로 판단할 수 없다.

## 4. 함정 — 결론을 틀리게 만든 것들

1. **시드는 8 개 이상.** 수치 하나만 바꿔도 처치 타이밍이 갈려 던전이 달라지고, 한 회차 층당 사망이 4.7 ↔ 8.4 로 흔들린다(README v870). 같은 시드끼리 짝지어 비교하지 말 것 — 첫 변화 뒤 난수가 갈려 만난 몹 자체가 다르다(v827: 혼령 182 ↔ 240). 특정 몹 조정은 총량보다 **개체당 지표**로(v827).
2. **사망 수는 '몇 방에 죽나'를 못 본다**('전체 점검(v871)') — 죽으면 60% 로 되살아나므로 한 방 상한 40% 든 32% 든 두 방이다. 상한·회복량 조정은 **피해/층 + 한 방 계산**으로 판단할 것.
3. **봇은 보스 패턴을 이해 못 한다**(점멸·장판·눈보라 · 거수전 회피 2,500번) — 보스전 시간·사망은 막끼리·조건끼리 비교에만. 새 몹 측정이 튀면 먼저 봇이 '사람이면 아는 공략'을 모르는지 볼 것(v871: 골렘 정면 무적을 몰라 궁수 2막 사망 19.7 → 봇 고친 뒤 3.0). 봇을 고쳤으면 **이전 빌드(대조 플래그)도 고친 봇으로 다시** 잰다(v829).
4. **측정 중 index.html 을 고치지 말 것** — 서버는 매 요청 파일을 새로 읽어 뒤에 뜨는 run 이 새 빌드를 탄다('2·3막 체감 조정' 계측 함정 ④). batch.sh 는 md5 가 바뀌면 새 run 을 안 띄우고 `batch-*.txt` 에 `TAINTED` 를 남긴다. 전/후는 두 빌드가 아니라 **한 빌드의 플래그**로 가른다(md5 검사 때문에 batch.sh 는 다른 빌드 서버를 거부한다).
5. **한 서버에 동시 4 개를 넘기지 말 것** — `page.goto` 가 시간 초과로 죽는다('용병 2단계' 계측 함정 ①). `-j` 는 최대 4, `-p 8899,8897` 이면 덜 바쁜 포트로 나눠 준다. 프리로드(`pw-preload.js`)가 goto 제한을 30 → 240초로 늘린다. 미세 측정 하네스를 봇과 같은 서버에 붙이지 말 것(v827).
6. **URL 플래그를 xargs 로 넘기지 말 것** — 따옴표가 벗겨져 `&` 가 셸 백그라운드 기호가 되고 대조군이 쿼리 없이 돌아 두 조건이 소수점까지 같았다('용병 2단계' 계측 함정 ①). batch.sh 는 배열 원소로 node 에 그대로 넘긴다. 플래그가 먹었는지는 결과로 확인(예: `&bal=0` 이면 끝 레벨이 달라진다).
7. **`pkill -f "node run.js"` 를 쓰지 말 것** — 패턴이 자기 셸 명령줄(heredoc 포함)에 걸려 셸이 죽는다(exit 144, '용병 2단계' 계측 함정 ②). `stop.sh`(pid 파일)로 끈다. 꼭 패턴이면 `pgrep -af "playbot/run[.]js"`.
8. 서버를 그냥 `&` 로 띄우면 Bash 호출이 끝날 때 같이 죽는다('혼령 히트앤런 빈도' 계측 함정) — batch.sh 는 `( setsid nohup … & )`.
9. **메인 루프에만 있는 시계**(보스 슬로모 `bossSlowTick` · 120층 `hsFallTick`)는 봇 루프가 대신 돌린다 — 메인 루프에 새 시계를 넣으면 `__botRun` 에도 넣을 것. 안 넣으면 보스를 잡아도 카드가 안 떠 회차가 안 끝난다(README v870).
10. 4막 층 시간·300초 초과는 대개 봇 끼임(흑요석·쓰러진 기둥 둘레, 빼내기 60~90번) — 게임 수치가 아니다(v870). 층 시간은 참고만.
11. 봇은 스킬을 안 쓰고 보상 카드는 첫 장 · 체력 40% 아래면 물약. 결과 JSON 에 용병 지표(딜·쓰러짐)는 없다 — 그게 필요하면 run 러너를 따로 써야 한다.
